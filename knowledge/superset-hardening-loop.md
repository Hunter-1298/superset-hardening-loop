`Hunter-1298/superset` is a fork of Apache Superset used as the target of an automated CVE
remediation loop. The controller lives in `Hunter-1298/superset-hardening-loop`; it opens the
tracking issues, starts remediation sessions with a per-kind ACU cap, polls their structured
output, waits for CI and Devin Review, and closes a finding only after a later complete scan of
`main` shows it is gone. Humans approve dispositions and merge; sessions never do.

Branches. `main` is the remediation branch and the PR target; it started from upstream tag `6.1.0`
(`c83fb2bb1dcfac41ac51bcebd82471f4a7180d18`). `upstream-master` mirrors apache/superset master for
comparison and is never a base or a target. `master` is the fork's old default and is left alone.
Nothing is ever pushed to, or opened against, `apache/superset`.

Dependencies. `requirements/*.txt` are generated by `./scripts/uv-pip-compile.sh` from
`pyproject.toml` and `requirements/*.in`; editing the `.txt` files by hand is a CI failure. Raise a
`pyproject.toml` upper bound only when the fix version needs it and say why in the PR.

Scanning. `.github/workflows/security-scan.yml` builds the immutable `lean` image, generates a Syft
SBOM, runs Trivy and Grype in raw mode (never suppressed) and policy mode (only documents under
`security/vex/approved/` are honoured), then starts the exact image (`lean-smoke`) and runs it
against Postgres and Redis (`app-runs`: migrations, health, login, dashboards, chart data, SQL Lab,
CSV export). `.trivyignore`, `.grype.yaml` and similar ignore files fail the `forbid-ignore-files`
job. Proposed VEX goes under `security/vex/proposed/`; only a human moves it to `approved/`.

Security model. `SECURITY.md` is authoritative. A finding is in scope when it lets a principal do
something the role and capability matrix does not entitle them to; Admin is fully trusted and
operator-controlled infrastructure is inside the trust boundary. Name the matrix row and the
assumed principal in any reachability or disposition write-up.

Conventions. Conventional Commit PR titles (`fix(deps):`, `build(docker):`, `fix(helm):`), one PR
per session, Apache license headers on new source files, type hints on new Python, pre-commit on
changed files before pushing, `UPDATING.md` for breaking changes. Record every command you ran in
the structured output's `tests_run`; never report a test you did not run. When a change needs a
decision outside the playbook's boundaries, return `blocked` with the reason rather than guessing.
